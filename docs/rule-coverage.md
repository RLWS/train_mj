# 规则覆盖状态

> 2026-10-28 更新：当前代码使用 `full_state_v2` 特征（turn/response state 11969/12012，候选 89/91），旧 bronze/silver/manifest/checkpoint 不兼容，需从原始 XML 重建。流程见 [full-state-training.md](full-state-training.md)，最终分析见 [training-analysis-2026-10-28.md](training-analysis-2026-10-28.md)，特征布局见 [model-inputs.md](model-inputs.md)。下文旧 run 结果属于历史 baseline。


更新时间：`2026-07-31`

本文只描述当前代码已经实现的规则边界。“能解析标签”“能判断牌形”“能生成候选”和“完整符合日麻规则”是不同层次，不应混为一谈。

## 1. 已实现

### 1.1 牌表示与状态

- 34 类基础牌与 `0m/0p/0s` 赤五精确表示。
- 四家精确手牌、弃牌河、副露、分数、立直状态和宝牌指示牌。
- 自家舍牌振听、临时振听和立直后振听的第一版状态。
- 当前巡目、最近弃牌、场风、自风、本场和立直棒等样本所需状态。

### 1.2 Tenhou 解析与副露解码

已解析：

- `GO`
- `UN`
- `TAIKYOKU`
- `INIT`
- 四家摸牌与弃牌
- `N`
- `DORA`
- `REACH`
- `AGARI`
- `RYUUKYOKU`

副露解码覆盖：

- `chi`
- `pon`
- `daiminkan`
- `ankan`
- `kakan`

解码器也能识别三麻 `nuki` 编码，但 `GameState` 不会应用其状态变化；项目当前只支持四麻，因此不能把这视为三麻能力。

### 1.3 回放校验

当前 ReplayValidator 已检查：

- `INIT` 起手为 13 张。
- 弃牌存在于当前手牌。
- 副露消耗牌存在于当前手牌。
- `chi/pon/daiminkan` 的来源和目标牌与最近一次弃牌一致。
- `kakan` 升级一个已有 `pon`。

### 1.4 turn 候选与样本

当前支持：

- `discard`
- `riichi_discard`
- `tsumo`
- `ankan`
- `kakan`
- `kyuushu_kyuuhai`

真实夹具已覆盖这些动作；2026-07-31 的 21 局 smoke 中已出现 1 条 `kakan` 样本。

### 1.5 response 候选与样本

当前支持：

- `pass`
- `chi`
- `pon`
- `daiminkan`
- `ron`
- `chankan`

基础边界：

- `chi` 只允许响应上家弃牌。
- 赤牌在规则候选与 Parquet 动作 JSON 中保留精确表示。
- 自家舍牌振听会检查完整等待牌集合与自家历史舍牌的交集。
- 本巡错过可和机会后，到自家下一次摸牌前阻止后续 `ron`。
- 立直后错过可和机会会持续阻止后续 `ron`。
- `kakan` 响应窗口可构建 `chankan` 样本；若抢杠成立，不会把该次 `kakan` 真正应用到回放状态。

### 1.6 手牌检查

当前支持：

- 标准四面子一雀头牌形。
- 七对子牌形。
- 国士无双牌形。
- 基础向听数、有效牌和 `riichi_discard` 所需的弃牌后听牌检查。

这里的“和牌判断”只表示牌形完成，不包含有役判断、和牌方式合法性、番符或点数。

## 2. 明确未实现或不完整

### 2.1 和牌、役与计分

- 完整役种判断。
- 无役和牌过滤；当前 `tsumo/ron/chankan` 候选只基于牌形和部分振听状态。
- 符、番、役满和点数计算。
- 里宝牌、杠宝牌、杠里宝牌影响。
- 点数移动、顺位和终局结算校验。
- 流局满贯。

### 2.2 立直边界

- 立直后的完整摸切锁定；当前仍可能枚举全部手牌弃牌。
- 立直玩家的完整吃碰杠限制。
- 立直后暗杠等待牌不变等限制。
- 一发状态。
- 牌山尾部、剩余牌数等完整立直条件。

### 2.3 荣和、振听与响应仲裁

- 更完整的和牌机会放弃语义和残余振听边界。
- 双响或多响；当前 response window 只处理遇到的第一条 `AGARI`。
- 多家响应的完整优先级和仲裁。
- 抢暗杠国士等特殊边界。
- `kakan` 响应窗口中 `ron` 与 `chankan` 的动作语义仍有重叠。

### 2.4 流局与牌局守恒

ReplayValidator 当前不检查：

- 136 张全局牌守恒和第五张牌。
- 完整摸弃顺序与每一步手牌张数节奏。
- 牌山、王牌和剩余牌数。
- `AGARI` / `RYUUKYOKU` 的规则合法性。
- 各类途中流局的完整条件。
- 终局分数变化。

### 2.5 候选特征边界

规则候选保留精确赤牌表示，但模型特征不一定能区分所有精确牌变体。特别是 turn 的 `ankan/kakan` 特征没有完整编码 `consumed_tiles/source`，部分赤牌精确候选可能得到相同向量。需要区分“规则对象不同”和“模型输入可分辨”。

## 3. 数据、训练与服务边界

已经落地：

- turn/response 特征预编码。
- 单任务与多任务训练。
- DDP 训练、分布式离线评估和 response calibration。
- 错例抽样、样本检查和事件回溯。
- 第一版 HTTP 候选排序服务。

尚未落地：

- value/risk 模型。
- 固定牌谱 `replay-eval` 和 `infer-on-state` 的真实业务逻辑。
- 服务端根据 state 生成合法动作。
- 在线对局 session 和平台代理。

API 要求调用方传入 `legal_actions`。服务端只做 schema、字段、动作种类和基础取值校验，不会根据局面重新证明候选动作合法。

## 4. 实际含义

当前仓库可以：

- 解析并回放真实天凤四麻牌谱。
- 在已覆盖边界内生成 turn/response 候选和监督标签。
- 构建大规模数据集并训练、评估、校准候选排序模型。
- 通过 HTTP 对调用方提供的候选动作排序。

当前仓库不能被描述为：

- 完整的日麻规则或计分引擎。
- 能独立验证任意在线局面合法性的服务。
- 已实现 value/self-play 的麻将智能体。
- 可直接驱动雀魂客户端的完整自动对局系统。
