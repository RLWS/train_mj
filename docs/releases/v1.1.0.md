# v1.1.0 Release Notes

发布日期：`2026-05-17`

这是冻结的历史发布快照。当前默认模型、DDP 状态和测试数量见 [v1.2.0.md](v1.2.0.md) 与 [../status.md](../status.md)。

本版本是仓库第一个“可作为本地发布点”的版本：`turn` 和 `response` 已完成初步验证，serving/API 第一版可用，P800 上已有单任务 improved、多任务 v1.1 与 v1.2 interleave 的对照证据。版本号定为 `v1.1.0`，因为已有 `v1.0.0` 标签，本轮主要是在保持 v1.0.0 单任务 baseline 可用的基础上增加多任务训练与服务接口。

## 发布时推荐默认组合

- `turn`：多任务 v1.1 checkpoint 是当时更均衡的候选 baseline。P800 test 指标达到 `top1=0.7169`、`top3=0.9538`、`top5=0.9884`，相对 2026-05-10 improved 单任务有明确提升。
- `response`：2026-05-10 improved 单任务 `pass_bias=0.3`。
- API：使用 `configs/api_local.yaml` 启动，外部调用必须传入 `legal_actions`，模型只在候选集合内排序。

## 主要内容

### 多任务训练

- 新增 `MultitaskMahjongPolicyNet`。
- 新增 `task: multitask` 训练入口，同一 checkpoint 可分别按 `turn` / `response` 做离线评估。
- `turn` 与 `response` 共享状态 encoder 主干，各自保留 state projection、action encoder 和 ranking head。
- 默认 P800 多任务配置回到 v1.1 epoch-sequential。
- v1.2 `batch_interleave` 保留为显式实验配置：`configs/experiments/multitask_p800_v1_2_interleave.yaml`。

### Serving/API

- 新增 `mjai/serving/`：checkpoint 加载、特征编码、候选排序、response `pass_bias` 选择和请求内核校验。
- 新增 `mjai/api/`：FastAPI app factory、路由、Pydantic schema、API key middleware、统一错误响应和 debug logging。
- 新增接口：
  - `GET /health`
  - `GET /v1/models`
  - `POST /v1/predict/turn`
  - `POST /v1/predict/response`
- 新增 CLI 启动入口：

```bash
python -m mjai.cli serve-api --config configs/api_local.yaml
```

### 评估与诊断

- 离线 `eval` 支持 streaming dataset，减少 valid/test split 常驻内存。
- `response` 评估补充 multi-candidate、pass/non-pass precision/recall/F1、false call、missed call、candidate-set 聚合和 confusion。
- 新增 `calibrate-response`，可扫描 `pass_bias` 并按 false call 目标选择 operating point。
- 新增 `sample-response-errors`，按 `label->pred` confusion 抽样 response 错例。
- 新增 `sample-turn-errors`，按 label kind 和 label rank 抽样 turn top-k 错例。

### 数据与训练链路

- `build-dataset` 支持 `--workers N` 并行构建。
- 样本写出预编码 `state_features_bin` 和 `candidate_features_bin`，训练/评估阶段不再逐 epoch 重新计算状态与动作特征。
- response train 默认可过滤 pass-only 单候选样本，valid/test 仍保留全量样本。
- checkpoint 继续输出 `best.pt`、`best_accuracy.pt`、`best_loss.pt`、`best_macro.pt`、`final.pt`，response 额外保留 `best_response.pt`。

## 关键取舍

- 多任务对 `turn` 明确有收益，可进入后续候选 baseline。
- 多任务 `response` 在 v1.1.0 发布时不能替代 2026-05-10 improved 单任务 response。
- v1.2 interleave 改善了部分 response macro 与 `daiminkan` 指标，但没有解决核心 false/missed/F1/少数类取舍，因此不作为默认主线。

## 已知缺陷

- API 第一版不生成合法动作，调用方必须提供 `legal_actions`。
- API 尚不维护在线对局 session，也不是完整自动对局代理。
- 规则引擎仍不是完整日麻规则/计分引擎，和牌机会放弃语义、途中流局、立直细节、多家荣和等边界仍需补齐。
- `response` 少数类、false call/missed call 取舍仍需继续优化。
- 发布时 DDP、value head、自动类别权重估计和分层采样尚未完成；DDP 后续已在 v1.2.0 完成第一版。
- `replay-eval` 与 `infer-on-state` 仍是占位命令。

## 升级注意

- 代码包版本已从 `0.1.0` 同步到 `1.1.0`。
- 修改 feature schema、parser/rules 或 split 逻辑后，必须重跑 `build-dataset` 和 `make-manifest`。
- release 不包含本地生成数据、run 归档、checkpoint、原始牌谱或机器私有配置。
- 若用 API 本地启动，请确认 `configs/api_local.yaml` 中 checkpoint 路径指向本机存在的模型文件。

后续变化见 [v1.2.0.md](v1.2.0.md)。
